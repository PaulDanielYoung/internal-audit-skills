# Receipt and source handoff

The receiving substantive workflow retains and indexes material before passing retained-source links and proposed RQ matches here. Originals are preserved under the engagement's `sources/`; identical retained copies are reused, changed versions kept apart, and original location and receipt date recorded in `sources/README.md`.

When invoked directly with unretained material, arrange that normal retention and indexing step with the receiving workflow or auditor first. Keep receipt outstanding until retained-source links exist; an unretained attachment is not a received-source link. Verbal answers require dated retained notes. Unrequested material follows normal retention without creating or changing a request row.

Propose the retained-source match and obtain auditor confirmation before marking a row Received. An auditor's explicit confirmation already supplied in the conversation is sufficient. Put uncertain entity, period, version, or substantive sufficiency to the caller or auditor rather than treating a possible match as satisfaction.

For a confirmed full response, mark the row Received and link the retained source in Received. For a confirmed partial response:

1. Mark the original Received and link the retained response.
2. Create a new Proposed row for the remainder under LIST-RULES.md, carrying applicable Needed by references. Link both IDs reciprocally in Notes and describe the supplied portion and remaining need.
3. Return the remaining information gap, new ID, retained-source link, and affected references. Receipt of the original is not satisfaction of all its needs.

Return each confirmed RQ reference to the receiving workflow for addition to the source's provenance entry in `sources/README.md`, so the row links to the source and the source index links back to the request. Source retention and indexing remain with that workflow. Include remaining gaps and affected references in the handoff required by SKILL.md; the owning skills update their own artifacts.
